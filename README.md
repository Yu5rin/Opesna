# Opesna

<img src="app/assets/icon_128.png" alt="Opesna のアイコン" width="96">

**スクリーンショットに注釈と説明文を添えて、操作手順書をすばやく作る個人向けのアプリです。**

画面を撮ってステップとして並べ、矢印や枠、番号、説明文を書き込み、PDF・HTML・Markdown・PNG に
エクスポートします。ユーザー登録やプランは無く、データはすべて手元のフォルダに保存するローカル完結型です。

## 主な特徴

- **画面を撮る。** 「キャプチャ」から、全画面（カーソルのあるディスプレイ）・特定のウィンドウを選んで
  撮るほか、手元の画像ファイルを読み込めます
- **操作を記録する。** 「記録」を押してから画面を操作すると、クリックのたびにその直前の画面を撮り、
  押した場所を囲んだステップを自動で作ります。クリックした部品の名前はステップの題に入ります。
  停止は記録中に出るインジケーターの「停止」ボタンか、`Ctrl+Shift+F9` で行います
- **注釈を書き込む。** 矢印・四角形・楕円・吹き出し・テキスト・ハイライト・モザイク・番号バッジ・トリミング。
  色と線の太さを選べ、書いたあとも動かしたり大きさを変えたりできます。モザイクだけは描いた時点で
  画像そのものに焼き込まれ（あとから外せません。取り消しは「元に戻す」で行います）、ほかの注釈は
  エクスポート時に画像へ合成されます
- **ステップを並べる。** 追加・削除・並べ替えができ、ステップごとに題と説明文を付けられます
- **フォルダで整理する。** サイドバーからプロジェクト用のフォルダを作成・名前変更・削除でき、
  各プロジェクトはカードのメニューから別のフォルダへ移動、またはフォルダの外へ出せます
- **テンプレートを選ぶ。** シンプル・2カラム・コンパクト・番号大きめ・ビジネス（ダーク）・メモ帳風の6種類
- **エクスポートする。** PDF・HTML・Markdown・PNG。エクスポートする前にプレビューで確かめられます。
  PNG は現在のステップ／すべてのステップから範囲を選べ、Markdown は画像を `<ファイル名>_images`
  フォルダに書き出して本文から相対パスで参照します。直前と同じ設定でもう一度出力したいときは
  「前回と同じ設定でエクスポート」（既定 `Ctrl+Shift+E`）が使えます
- **手元に保存する。** 作ったものは `.opn` 形式のファイルで保存し、フォルダに分けて管理できます。
  自動保存（既定で5分ごと）と、元に戻す・やり直しがあります。保存前にアプリが異常終了しても、
  次に起動したときに自動保存からの復元を選べます
- **ショートカットを変えられる。** 環境設定の「ショートカット」タブから、各操作のキーを割り当て直せます

## 動作環境

- Windows 10 以降（64ビット）

## インストール

1. [Releases の最新版](https://github.com/Yu5rin/Opesna/releases/latest) から `Opesna.exe` を落とします
2. 好きなフォルダに置いて、ダブルクリックで起動します。インストーラーはありません

初めて起動すると、`Opesna.exe` と同じフォルダに `data` と `config` のフォルダができます。
作ったものと設定はここに入るので、自分で書き込めるフォルダ（ドキュメントやデスクトップの下など）に
置いてください。

コード署名をしていないため、初めての起動で Windows の SmartScreen が警告を出すことがあります。
その場合は「詳細情報」から「実行」を選びます。

## 更新

環境設定の「バージョン情報」タブから、新しい版が出ていないか確認できます。「更新を確認」を押すと
その場で問い合わせ、新しい版があれば「更新する」でダウンロードと入れ替えまで行います
（未保存の変更があれば、先に保存するか確認します）。

起動のたびに自動でも確認します（設定「起動時に新しい版があるか確認する」。既定でオン）。
見つかると画面上部の帯で知らせるだけで、入れ替えは「更新する」を押したときだけ行います。
オフにすれば、起動時の通信は一切行いません。

`Opesna.exe` が置かれているフォルダに書き込めない場所（`Program Files` など）に置いている場合は、
自動では入れ替えられません。「リリースページを開く」から手動で更新してください。新しい
`Opesna.exe` を Releases から落とし、前のものと差し替えれば、`data` と `config` のフォルダは
そのまま引き継げます。

## 使い方

1. ホーム画面の「新規作成」でプロジェクトを作ります（「画像から作成」で手元の画像から始めることもできます）
2. ツールバーの「キャプチャ」で画面を撮るか、「記録」で操作を記録してステップを作ります
3. 注釈ツールで書き込み、右側の「ステップ説明」に題と説明文を入れます
4. 「テンプレート」で見た目を選び、「エクスポート」で出力します

## データの保存場所

既定では `Opesna.exe` と同じフォルダの下に保存します。

| フォルダ | 中身 |
|---|---|
| `data/projects` | 作ったプロジェクト（`.opn`）。サイドバーのフォルダごとに分かれる |
| `data/exports` | エクスポートしたファイルの既定の保存先 |
| `data/autosave` | 自動保存の復旧用データ。保存前にアプリが異常終了したときの復元に使う |
| `config` | 設定・ショートカット・最近開いたファイル（JSON。直接編集もできます） |

`Opesna.exe` のフォルダに書き込めない場所（`Program Files` など）に置いている場合は、
`%APPDATA%\Opesna` の下（`data`・`config` とも同じ構成）に保存します。

`data` と `config` のフォルダをコピーすれば、すべてのデータを控えられます。

前回終了時に保存されなかったプロジェクトが残っていると、次にアプリを起動したときに
復元するか尋ねられます。

Opesna は、更新の確認・ダウンロードのとき以外はインターネットに接続しません。通信する相手は
GitHub（github.com と、そこから転送される配布物の置き場）だけで、送るのは通常の HTTP の
問い合わせだけです。作った資料や画像を送ることはありません。起動時の確認は設定でオフにでき、
オフにすれば「更新を確認」を押したとき以外は通信しません（詳しくは「更新」の節）。

## 開発

Electron で作っています。

```
npm install
npm start
```

配布用の実行ファイルは次で作ります。

```
npm run build:win   # Windows 向けの Opesna.exe（dist/ に出る）
npm run build:mac   # macOS 向けの zip（リリースには載せていない）
```

`v1.0.1` のようなタグを push すると、`.github/workflows/release.yml` が Windows 版を作って
Releases に下書きを用意します。

タグの `v` は必ず**半角**で打ちます（`v1.0.2` は動き、全角の `ｖ1.0.2` は動かない）。ワークフローは
`v*.*.*` に合うタグでしか動かず、全角の `ｖ` では何も起きません。最初の版のタグとリリースは、
ワークフローを入れる前に全角の `ｖ1.0.0` で作ったものです。変更の記録は `CHANGELOG.txt` にあります。
